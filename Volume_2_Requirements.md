REQUIREMENTS CATALOGUE WITH STABLE IDs

The following sections define explicitly tracked functional requirements with stable IDs.

## Functional Requirements
- **REQ-HOME-001**: The system must provide a primary landing dashboard with market summary widgets.
- **REQ-TRADE-001**: The system must provide a Strategy Builder to construct custom options strategies.
- **REQ-TRADE-002**: The system must include a Strategy Wizard for guided strategy construction.
- **REQ-TRADE-003**: The system must provide Expiry Trades features.
- **REQ-TRADE-004**: The system must provide Easy Options features.
- **REQ-TRADE-005**: The system must allow Draft Portfolios.
- **REQ-TRADE-006**: The system must include Mindful Trading limits/tracking.
- **REQ-TRADE-007**: The system must include Learn Options Strategies educational modules.
- **REQ-ANALYSE-001**: The system must provide an interactive Option Chain with real-time greeks and Ltp.
- **REQ-ANALYSE-002**: The system must provide Open Interest analytics.
- **REQ-ANALYSE-003**: The system must track and display OI Change.
- **REQ-ANALYSE-004**: The system must display Multi Strike OI charts.
- **REQ-ANALYSE-005**: The system must track FII/DII Data.
- **REQ-ANALYSE-006**: The system must provide Live Options Charts.
- **REQ-ANALYSE-007**: The system must provide Multi Straddle / Strangle Charts.
- **REQ-ANALYSE-008**: The system must provide general Stock Data.
- **REQ-ANALYSE-009**: The system must include a Real-time Screener.
- **REQ-ANALYSE-010**: The system must provide Technical Signals.
- **REQ-ANALYSE-011**: The system must offer Market Analysis summaries.
- **REQ-ANALYSE-012**: The system must provide an IV Chart.
- **REQ-ANALYSE-013**: The system must include an Economic Calendar.
- **REQ-ANALYSE-014**: The system must include a Stock Results Calendar.
- **REQ-ANALYSE-015**: The system must include a Holiday Calendar.
- **REQ-ANALYSE-016**: The system must provide a Market Heatmap.
- **REQ-WATCHLIST-001**: The system must allow users to manage custom Watchlists.
- **REQ-POSITIONS-001**: The system must display active trading Positions.
- **REQ-ORDERS-001**: The system must display trading Orders.
- **REQ-COMMUNITY-001**: The system must provide Verified P&L tracking (where approved).
- **REQ-COMMUNITY-002**: The system must include Trader showcase analytics (where approved).
- **REQ-USER-001**: The system must provide Profile and Settings pages.
- **REQ-USER-002**: The system must support Broker-related UI integrations where documented.
- **REQ-USER-003**: The system must allow Chart and Theme preferences.

## Non-Functional Requirements (Scalability & Architecture)
- **REQ-NFR-001**: The application must be stateless to support horizontal scalability.
- **REQ-NFR-002**: The system must implement robust caching layers.
- **REQ-NFR-003**: Database scalability must handle high-throughput read/write without locking constraints.
- **REQ-NFR-004**: Realtime scalability must support mass-concurrent WebSocket connections.
- **REQ-NFR-005**: Queue scalability must support asynchronous event processing.
- **REQ-NFR-006**: The system must implement strict rate limiting to prevent abuse.
- **REQ-NFR-007**: Failure isolation and graceful degradation must be implemented for external provider outages.
- **REQ-NFR-008**: The system must support DAU scale of 100,000–200,000 users.

*(Note: Exact numerical capacities for servers/connections are `[DECISION REQUIRED]` and must be benchmarked, not arbitrarily invented.)*
