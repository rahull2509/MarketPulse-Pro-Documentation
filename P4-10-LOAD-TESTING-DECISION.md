# P4-10 LOAD TESTING DECISION
**Phase:** P4-10 Production Hardening

## 1. Framework
- Approved framework: **k6**
- Load tests MUST be maintained separately from production application logic.

## 2. 100K DAU Workload Profile
100k DAU = 100,000 unique users performing at least one authenticated application interaction during a rolling 24-hour period. (NOT 100k concurrent users).

- Peak concurrent authenticated users: 5,000
- Average concurrent authenticated users: 1,500
- Peak REST request rate: 500 requests/second
- Average REST request rate: 150 requests/second
- Peak WebSocket connections: 5,000 concurrent
- Peak portfolio requests: 100 requests/second
- Peak order requests: 20 requests/second
- Peak broker-read requests generated by application: 200 requests/second
- Redis operation target: 2,000 operations/second
- PostgreSQL operation target: 500 operations/second
- Portfolio cache hit ratio: >= 80% under steady-state

## 3. Load-test Phases
- Ramp-up: 15 minutes
- Steady-state: 60 minutes
- Spike test: 10 minutes
- Soak test: 4 hours

## 4. Latency Acceptance (Pass Criteria)
- p50 <= 200 ms
- p95 <= 500 ms
- p99 <= 1000 ms
- Maximum application error rate: <= 1%

## 5. Scenarios & Authentication
- REST API traffic, authenticated users, portfolio, broker read, order execution, WebSocket connections, reconnect behavior, cache hit/miss.
- MUST NOT use real production broker credentials (use test accounts). No real-money order execution.
