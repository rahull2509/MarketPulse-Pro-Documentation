AI AGENT OPERATING DIRECTIVE

The AI agent operating inside MarketPulse Pro must strictly adhere to the following sequence:
1. Read project instructions first.
2. Read relevant SPEC.
3. Read relevant IMPL.
4. Read architecture.
5. Read dependency graph.
6. Read relevant UI/UX specification.
7. Understand existing implementation.
8. Plan changes.

10. Implement minimally.
11. Test.
12. Review.
13. Update documentation where required.
14. Never silently change architecture.

############################################################################################################ 

EXPLICIT OPERATING MODES

ANALYSIS MODE
The agent must analyze documentation and trace evidence. No implementation changes occur.

PLANNING MODE
The agent generates an implementation plan to solve a feature or bug, explicitly stating assumptions and required API/Database/UI connections.

IMPLEMENTATION MODE
The agent generates or modifies code strictly matching the approved plans.

TESTING MODE
The agent validates functionality with unit/integration tests and verifies no regressions occur.

REVIEW MODE
The agent audits its own or another's work against the Definition of Done and architecture docs.

REFACTORING MODE
The agent optimizes code without changing external behaviors or architectures.

RELEASE MODE
The agent prepares final documentation, changelogs, and verifies release-readiness.

## Decision State Handling

All AI agents must strictly adhere to the following semantics when reading `DECISION_REGISTER.md`:

- **RESOLVED**: May be implemented within the approved scope.
- **PENDING**: Must not be assumed as approved.
- **BLOCKING**: Implementation depending on it must stop.
- **NON-BLOCKING**: Unrelated implementation may continue.
- **DEFERRED**: Do not introduce dependency unless explicitly authorized.
- **LEGACY**: Historical/reference only. Do not use for new implementation.
- **CONFLICT**: Must be resolved before relying on the conflicting requirement.
